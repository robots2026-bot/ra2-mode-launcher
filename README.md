# RA2 Mode Launcher

一个面向本机《尤里的复仇》安装的独立 RA2 经典模式启动器原型。

- 底层运行 `gamemd-spawn.exe`，不是纯 RA2 的 `game.exe`。
- 可切换 CnCNet Spawner 的 RA2 经典规则和尤里复仇规则。
- 支持遭遇战地图、国家、颜色、队伍、AI 难度、固定出生点、全图可见和 `.SAV` 存档加载。
- 配套新版 cnc-ddraw 时，单人固定引擎最快档，由限速器统一控制 1–1000 整数目标或不限速；旧组件保留原版启动速度。
- 新建对局会给超时空军团兵的普通、精英与特殊武器使用独立弹道，使其能够隔墙冷冻目标，并将射程分别设为 8、9、10 格，同时不改变其他 `InvisibleLow` 武器。
- 参战位置按照地图容量固定显示，可逐个设置为玩家、电脑、开放或关闭；存档列表优先显示游戏内填写的存档名称。
- 新游戏加载 Ares、CnCNet Spawner 和 Phobos；读档时检查存档摘要，启动器生成的 Ares/Phobos 存档使用相同扩展组合读取，旧式无扩展存档仍只加载 CnCNet Spawner。
- 日常运行、地图扫描、存档、配置和维护都只访问当前游戏目录 `D:\Software\RA2Mode`，不依赖旧安装目录。
- 启动器首页先选择“创建房间”、“加入局域网房间”或“加载本地存档”；只有创建房间后才会监听房间端口。
- 首页局域网大厅会自动刷新对局列表，并显示选中房间的本地地图缩略图、模式、人数、速度、资金、规则、地图哈希与关键组件兼容性。
- 大厅与当前房间同时布局在一个主窗口中：左侧始终显示局域网房间列表和所选对局详情，右侧显示当前房间的地图、玩家、规则与准备状态。
- 进入房间后，一名真人时按单机遭遇战启动，多名真人时按局域网启动，地图、玩家和规则始终在同一个房间界面中。
- 房主可修改地图、全局规则、电脑和开放/关闭位置；客户端只能修改自己的国家、颜色、队伍和出生点并准备。房主修改全局配置后会清除全员准备状态。
- 局域网支持 UDP 1232 房间发现、按 IP 加入、TCP 1233 房间状态与地图同步，并由 CnCNet Spawner 使用 UDP 1234 启动真人对战；启动前会校验地图及关键 EXE/DLL/MIX 指纹。

## 构建

项目源码单独由 Git 管理。构建时使用项目目录内 `vendor\package_9.3.3\package` 中的 CnCNet 9.3.3 依赖；体积较大的 `vendor` 内容不纳入本仓库。克隆后需自行将官方 9.3.3 包解压到该目录，再执行构建。

```powershell
dotnet build .\Ra2ModeLauncher.csproj -c Release
```

发布和刷新当前游戏目录：

```powershell
dotnet publish .\Ra2ModeLauncher.csproj -c Release --self-contained false
.\deploy-runtime.ps1
```

当前目录需要预先包含合法的游戏资源（例如 `ra2.mix`）。部署脚本只使用当前目录与项目内的官方 CnCNet 9.3.3 组件，不再访问旧安装目录；同时给 `gamemd-spawn.exe` 应用已经验证过的“驻军建筑被超时空移除”崩溃修复。原始 Spawner 会保留为 `gamemd-spawn.exe.official-9.3.3`。

## 当前边界

局域网协议测试（不启动游戏、不修改存档）：

```powershell
dotnet run --project .\tests\LanProtocolSmoke -c Release
```

参战位置按固定行号保留；切换电脑、开放、关闭，以及真人加入、退出，都不重排其他行。空位不提供“玩家”选项，真人加入时自动占用开放位置。

房间具备等待、同步、游戏中状态。联机开局前所有电脑先校验组件并生成本地配置，任一检查失败则取消开局；游戏中禁止加入或修改设置，全部玩家退出后恢复等待。此版本使用协议 5，联机双方必须更新启动器。状态消息缓存地图，未改变地图时不重复传输内容。协议测试不等同于两台电脑实际游戏验收。

当前联机范围是同一局域网，不包含互联网大厅、NAT 穿透或公网中继。`.SAV` 读档仍是本机功能，不通过房间同步。

## 游戏辅助

底部“启用生产连点器”开关控制生产栏批量点击，不再持续自动点击，也没有单独的全局启停快捷键。开启后，在标准尤里复仇右侧生产图标上按 Ctrl＋左键，松开鼠标后发送100次左键点击；Shift＋右键完全交给游戏原生处理，加载器不拦截、不补发右键（尤里复仇通常按住Shift右击两次，先暂停再取消）。点击间隔默认10毫秒，可调10–5000毫秒（实际频率受Windows计时器和游戏处理速度影响）。

批量点击期间请保持鼠标在同一图标上；移动超过3像素、切出游戏、关闭开关或进行其他鼠标按键操作会停止批量点击。仅处理当前运行目录的游戏窗口，优先读取RA2MD.INI的实际游戏分辨率识别标准168像素宽的右侧生产栏，排除雷达、分类按钮和底部滚动区域；自定义皮肤、非标准缩放或非标准布局需另行适配。

这是输入辅助，发送次数不等于成功加入队列的数量；建造上限、工厂状态和资金等规则仍由游戏决定。当前Phobos 0.4.0.2不提供后续版本的建筑生产队列，不能据此实现建筑排队100个；批量生产使用系统鼠标输入，按下与松开分开发送，避免游戏忽略瞬时点击；发送成功仍需在实际游戏中验收士兵、坦克的队列变化。

启动时开启 QuickExit，并让渲染器把关闭请求交给游戏；请重新启动游戏后验证 Alt+F4 和任务栏关闭。退出前请保存进度。

新建单人和局域网对局的临时地图会设置 [General] MaximumQueuedObjects=100，原始地图保持不变。此设置提高生产队列容量，不解除特殊单位的 BuildLimit；已有存档不追溯修改。Ctrl＋左键发送100次点击，期间保持鼠标在图标上，移动鼠标或切换窗口会停止。

局内性能面板：右上方使用半透明背景，仅常驻显示速度、游戏引擎 FPS 和显示器刷新率。开局限速存在时附在速度后，联机时显示锁定状态。CPU、内存、运行时长、分辨率、无效帧采样、未实现的渲染 FPS 和常驻快捷键说明已移除；调速提示显示 3 秒后消失。Ctrl+Alt+↑/↓按每次 5 调整目标，Ctrl+Alt+0不限速、Ctrl+Alt+1设为60、Ctrl+Alt+S输入自定义目标，Ctrl+Alt+F10隐藏/显示；仅已适配版本的单人对局允许调速。新版组件支持局内更新限速器；旧组件不提供此调速能力。目标值是推进上限，实际速度受机器负载影响。面板随游戏窗口定位、鼠标穿透、不激活窗口，切换到其他程序自动隐藏。

## 多人速度控制

房主在开局前选择速度，修改后所有玩家重新准备。普通档使用原生 GameSpeed，cnc-ddraw 的额外推进限速设为 -1；75/90/120 和不限速使用 GameSpeed=0，前者按目标设置 maxgameticks，后者设为 -1。这些自定义档标记为“联机实验”，尚未完成真实双机推进速率验收。

协议 5 要求联机双方升级。组件校验包含 ddraw.dll；启动检查同时写入并回读全局和 gamemd-spawn 专属 maxgameticks，统一该游戏的 limiter_type=0，防止专属配置覆盖房主速度。spawn.ini 设置 DisableGameSpeed=true，联机局内调速快捷键仍被拒绝，HUD 显示局内锁定。游戏中房主也不能改速。独立渲染 maxfps 和其他游戏的配置保持原值。

测试：`dotnet run --project tests/LanSpeedSmoke -c Release` 验证所有预设的房主/玩家配置、专属覆盖、锁定和组件差异；`dotnet run --project tests/LanProtocolSmoke -c Release` 验证改速清除准备、旧协议拒绝、失败取消开局和游戏中锁定。测试未启动真实游戏，不代表多人实际速度已达到设定目标。
## 单人速度组件构建与更新

依次运行 native/cnc-speed/build.ps1、native/cnc-speed/test.ps1，再 dotnet publish -c Release。构建使用锁定提交的源码清单和本机 MSVC，发布目录包含 native-runtime/ddraw.dll 及许可证。退出游戏和加载器后，运行 install-speed-update.ps1 同时更新加载器和游戏根目录 DLL；脚本逐文件备份、校验，失败恢复。不要只复制加载器文件。

单人运行中可设置 1–1000 的整数目标或不限速；不保证达到目标，也不提供任意小数速度。多人自定义整数速度须由房主开局前设置并全员重新准备，局内锁定。DLL 的原生计时测试已通过，真实游戏推进和双机对战仍需验收。

开局的速度选择只决定初始速度，不构成局内可选速度的上限。单人快捷键和自定义输入直接替换当前限速器目标；例如初始30仍可切换120、1000或不限速。原版速度菜单由统一控制器替代，使用上述快捷键修改。

退出处理容忍游戏进程在窗口查询期间消失；正常退出不因失效进程号使面板报错。房间启动的游戏退出码记录到 launcher-startup.log，供区分正常退出与异常终止。
